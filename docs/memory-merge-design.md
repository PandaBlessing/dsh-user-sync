# 多机用户记忆融合设计（只设计，不实现）

> 约束：**不能修改 DSH 的行为**；插件只处理「同步的用户记忆文件」；**不依赖人工**。
> 目标：多台机器的用户级记忆随时间出现偏差时自动融合，不直接覆盖。

## 1. 范围

| 文件 | 处理 |
|---|---|
| `~/.dsh/AGENTS.md` | 条目级自动合并 |
| `~/.dsh/memories/*.md`、`MEMORY.md` | 条目级自动合并 |
| 其它模块（配置/插件/技能） | 保持 LWW（整文件覆盖，非记忆） |

## 2. 关键点：谁来拆、谁来合

- **拆分由插件做**（同步层纯函数，确定性规则）；
- **合并在插件做**（条目级三方合并）；
- **不靠 DSH**（不改 DSH 行为）、**不靠 LLM**（可复现、可测试）、**不靠人工**（要求）。

## 3. 条目拆分规则（纯函数，确定性）

输入：一个 Markdown 文本 → 输出有序条目列表。

| 规则 | 说明 |
|---|---|
| 标题行（`#` 开头） | 独立条目（kind=`heading`），同时作为后续块的章节归属 |
| 空行分隔的段落 | 独立条目（kind=`paragraph`，含多行） |
| 列表项（`- ` / `* ` / `1. ` 开头） | 独立条目（kind=`list`）；缩进续行归入该条目；嵌套列表按缩进归入父条目 |
| 围栏代码块（``` … ```） | 整体一个条目（kind=`code`），不拆内部 |
| 表格（`|` 行连续） | 整体一个条目（kind=`table`） |

- 条目 `id` = 规范化文本（去首尾空白、压缩连续空白、统一换行）的 SHA-256 前 16 位；
- 拆分结果保留 `lineStart/lineEnd`，便于写回；
- 同一文件 → 同一拆分结果（稳定，便于测试与合并顺序固定）。

## 4. 合并算法（条目级三方合并）

输入：`base`（上次同步基线）、`local`（本机当前）、`remote`（远端包内文件）。

```
按章节分组（heading 条目作为分组键），每组内：
  - 条目集合：base / local / remote 各自的条目列表
  - 对每个条目：
      1) id 在 local 与 remote 都出现 → 去重（保留 local 一份）
      2) id 只在 local → 本地新增，保留
      3) id 只在 remote → 远端新增，追加（按远端顺序）
      4) local 与 remote 各有一个「相似」条目（相似度 ≥ 0.8 且长度比 ≥ 0.6）
         → 视为同一条目的修改，取「较新」的（条目来源文件的 mtime；同 mtime 取 remote）
      5) 条目在 base 存在、local 删除、remote 修改 → 保留 remote（不删除）
      6) 条目在 base 存在、local 修改、remote 删除 → 保留 local
      7) 两边都删除 → 删除
输出：按「base 顺序 → local 新增 → remote 新增」排列，章节顺序沿用 base（新章节追加末尾）。
```

相似度：Levenshtein 距离归一化（`1 - 距离/较长长度`）；仅对同 kind、同章节内的条目比较，避免跨章节误合并。

## 5. 同步流程（先合并，再上传）

```
check：远端包 vs 基线 vs 本机 → 判定 in-sync / push / merge-required
apply：拉取远端包 → 对记忆文件做条目级合并 → 写回本机 → 更新基线
upload：打包前若远端比基线新 → 先合并（防止 A 覆盖 B）→ 再上传合并结果
```

- 基线存储：`~/.dsh/user-sync/baseline/<相对路径>`（插件目录，不动 DSH 结构）；
- 每次成功 apply/upload 后刷新基线；
- 合并结果与本机相同 → 不写盘；与远端相同 → 不上传（避免无意义变更）。

## 6. 边界情况

| 场景 | 处理 |
|---|---|
| 首次同步（无基线） | 退化为 LWW 并建立基线 |
| 远端无该文件 | 本机保留并上传 |
| 非 Markdown/二进制 | 回退 LWW |
| 全部条目相同 | in-sync，不写盘 |
| 同一章节大量相似改写 | 按「取新」策略，不双保留、不膨胀 |

## 7. 与「不能靠人工」的对应

- 冲突不再产生 `<<<<<<<` 标记；
- 相似修改取新（不双保留）→ 文件不膨胀；
- 删除冲突保留一侧 → 不丢内容；
- 用户无需任何操作。

## 8. 风险与限制

| 风险 | 说明 | 缓解 |
|---|---|---|
| 相似误合并 | 两条不同但相似的约定被判为修改 → 丢细节 | 阈值可调；只在同章节同 kind 内比较；日志记录被覆盖内容 |
| 拆分不理想 | 极端 Markdown（跨行列表、深嵌套） | 规则覆盖常见形态；异常时整段作为一个条目 |
| 顺序抖动 | 不同机器合并顺序不同导致反复上传 | 固定排序（base 顺序优先） |
| 基线丢失 | 无法三方合并 | 退化为 LWW + 重建基线 |
| 可追溯性 | 取新策略会覆盖旧表述 | 合并前把旧版本备份到 `user-sync/merged-backup/`（可选保留 N 天） |

## 9. 工作量估算（如需实现）

| 部分 | 内容 | 量 |
|---|---|---|
| `src/merge.ts` | 拆分 + 相似度 + 条目级三方合并 | ~300 行 |
| `src/sync.ts` | check/apply/upload 集成 + 基线 | ~120 行 |
| 备份 | `merged-backup/`（可选） | ~30 行 |
| 测试 | 拆分/合并/相似/删除/顺序 + 双机 e2e | ~40 用例 |

## 10. 讨论记录（被否方案）

| 方案 | 被否原因 |
|---|---|
| 冲突标记 + 人工合并 | 不能靠人工 |
| 冲突双保留 | 文件膨胀、语义重复（用户否定） |
| 改造 DSH 记忆结构 | 不能修改 DSH 行为 |
| LLM 语义融合 | 引入模型依赖、不可复现 |
