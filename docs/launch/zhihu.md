## 正文

### 先讲个场景

上个月换了台机器，装好 DeepSeek Harness（DSH）之后打开一看：技能没了、插件没了、`AGENTS.md` 里攒了几个月的记忆也没了。那一刻我盯着空白的设置页，第一次意识到——**我每天都在给 DSH「攒资产」，但从来没想过这些资产能不能带走**。

于是我把 `~/.dsh` 整个目录拷了过去。结果更糟：

- 带了一堆只属于旧机器的状态（会话、缓存、临时配置）；
- 插件在 `package.json` 里声明了，但 `node_modules` 没装，面板报错；
- 有些配置文件里有密钥，我根本不敢直接传网盘。

拷来拷去，最后变成一个手工活：挑文件、重装插件、改配置。一次还好，但我有台式机 + 笔记本，来回切换三四次就崩溃了。

### 为什么不直接用网盘同步 `~/.dsh`

我试过，问题有三个：

1. **粒度太粗**：`~/.dsh` 里既有用户级资产（技能、插件清单、配置、记忆），也有机器级状态（会话、缓存、运行态）。全量同步会把「不该搬的」也搬过去；
2. **没有一致性保证**：网盘同步是后写覆盖，两边同时改就悄悄丢数据；
3. **隐私风险**：目录里可能混着 token、`.env`、私钥，网盘/云盘同步等于全量上传。

所以我想要的其实是一个**只同步「用户级资产」、有确认和快照、能扫描敏感文件**的东西。

### 我做的插件：dsh-user-sync

一句话：**把 DSH 的四类用户级资产打包上传，换机一键恢复。**

四类资产：

| 资产 | 位置 |
|---|---|
| 技能 | `~/.agents/skills` |
| 插件清单 | profile 的 `package.json`、锁文件、`cordis.yml` |
| 配置 | `cordis.patch.yml`（含自定义 agent 预设） |
| 用户记忆 | `AGENTS.md` + `memories/` 下的 MARK/KEY 记忆 |

**使用流程**（面板里操作，不需要记命令）：

1. 设置 → 设置同步 → 同意并启用；
2. 勾选同步范围；
3. 点「上传用户配置」→ 打包上传；
4. 新机器装同一个插件 → 点「从远端同步」→ 覆盖前弹窗确认 → 完成。

### 几个我认为关键的细节

**① 敏感数据硬拒绝**

上传前会扫一遍文件：文件名黑名单 + 内容模式匹配，命中就直接拒绝打包，并列出是哪个文件哪一行。不是「警告一下」，是**硬拒绝**。因为我知道大部分人不会认真看警告。

**② 缺插件自动装回**

远端包里带了 `manifest.dependencies`。恢复时会按清单自动 `pnpm add` 缺失的插件，装完列出「已装 / 失败 / 需要手动放回（link: 本地包）」。换机最烦的「插件一个个装」，这一步省掉了。

**③ 覆盖前先快照，再确认**

「从远端同步」不是无脑覆盖：先本地生成 `pre-restore` 快照，再弹窗让你确认覆盖范围，确认后才写盘。写坏了还能从快照回退。

**④ 没有运营方账号**

用 DSH 官方账号 id 派生 `accountKey` 自动配对，不需要注册、不需要登录第三方后台。数据走 HTTPS 到服务端，服务端再落到坚果云 WebDAV；**远端只保留 1 份包，上传即覆盖**。

**⑤ 可以自建服务端**

服务端是纯 `node:http`、零第三方依赖。不想用公共实例的话，照 `docs/deploy.md` 部署一个自己的，在 `state.json` 写 `baseUrl` 指过去就行。

### 它没解决的问题（坦白）

- 会话、项目记忆、缓存在设计上不参与同步（那是机器级状态）；
- `link:` 本地依赖没法自动搬，需要手工放回目标机；
- 目前只验证了 Windows / macOS，Linux 未测；
- 公共实例是单节点，坚果云单账号有流量配额。

### 安装

```bash
cd ~/.dsh/profiles/desktop
pnpm add @pandablessing/dsh-user-sync
# 重启 DSH → 设置 → 设置同步
```
